# Support

## Where to ask

- **Bug:** use the [bug report](https://github.com/KavinduNirmal/circa-archive/issues/new?template=bug_report.yml) form. Include the revision, environment, reproduction steps, expected behavior, and actual behavior.
- **Feature or design proposal:** use the [feature proposal](https://github.com/KavinduNirmal/circa-archive/issues/new?template=feature_request.yml) form.
- **Documentation gap:** use the [documentation form](https://github.com/KavinduNirmal/circa-archive/issues/new?template=documentation.yml) or open a `docs/<topic>` pull request directly.
- **Question:** open a blank issue with enough context to answer without a follow-up round trip.
- **Security vulnerability:** follow [SECURITY.md](SECURITY.md) and report it privately. Do not open a public issue.
- **Code of conduct concern:** email **kavindunirmald@gmail.com** privately.

## Before opening an issue

1. Search open and closed issues for the same problem.
2. Read the [README](README.md), [CONTRIBUTING.md](CONTRIBUTING.md), and the relevant [client documentation](client/README.md).
3. Reproduce on the latest `develop` branch and include the commit.
4. Redact secrets, personal information, and private story content from logs and screenshots.

## What to expect

CIRCA Archive is maintained on a best-effort basis. There is no support contract, guaranteed response time, or bug bounty. Security reports are handled privately; ordinary issues are triaged when maintainer time allows. Pull requests that fix a reported problem are welcome and usually move faster than a request alone.
