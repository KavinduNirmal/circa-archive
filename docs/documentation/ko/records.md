# 기록 쓰기

기록은 선택적인 YAML 헤더를 가진 마크다운이며, 한 번의 파싱이 두 판본에 쓰입니다.

## 기록의 구조

기록은 하나의 마크다운 문서입니다. YAML 헤더가 필드를 담고, 본문이 독자가 보는 내용입니다. 2단계 제목은 이동 가능한 섹션을 시작하고, 3단계 제목은 그 안에 머뭅니다.

```markdown
---
circa_code: CIRCA-S-03007
incident_ref: INC-03007
title: The Unwalled Door
type: DISCOVERY
status: FILED
severity: S
originator: H. Kim
filed_date: 2004-09-12
last_revision: 2004-09-14
classification: LEVEL 3
clearance: REVIEWER
related:
  - INC-00907
tags:
  - door
---

# The Unwalled Door

## Brief

A free-standing door in a pasture in Gangwon Province.
```

> [!NOTE]
> 헤더는 본문이 아니라 데이터입니다
>
> 파서는 렌더링 전에 YAML 블록을 제거합니다. 텍스트로 출력되지 않고, 산문 블록으로 클라이언트에 전송되지도 않습니다.

## 헤더 필드

프론트매터는 파싱되어 메타데이터로 보관됩니다. 카탈로그의 기준은 여전히 아카이브 색인이므로, 기록 본문이 자기 헤더와 다를 수 있습니다. 실제로 하나는 의도적으로 다릅니다. 파이프라인은 이를 화해시키지 않고 불일치로 보고합니다.

| 필드 | 의미 |
| --- | --- |
| `circa_code` | 이 기록을 인용할 때 쓰는 코드. |
| `incident_ref` | 기록이 속한 사건. |
| `title` | 문서에 인쇄되는 제목. |
| `type` | DISCOVERY, INCIDENT, EXPLORATION, RUMOR 중 하나. |
| `status` | 문서가 선언하는 접수 상태. |
| `severity` | S, A, B — 분류의 심각도. |
| `originator` | 바이라인에 오르는 이름. |
| `filed_date` | ISO 형식의 접수일과 최종 개정일. |
| `classification` | 접근 등급과 요구되는 열람 허가. |
| `related / tags` | 상호 참조와 레이블. 둘 다 목록입니다. |

## 섹션과 앵커

독자가 이동할 수 있어야 하는 섹션에는 2단계 제목을, 그 안의 구조에는 3단계 제목을 쓰세요. 리더의 페이지 레일은 2단계 제목으로 만들어지고, 코드 펜스 안의 제목은 무시됩니다.

기록 이름은 서류 제목처럼, 본문은 타자기 같은 서체로 조판됩니다. 관리할 풍부한 레이아웃이 없기에 기록은 판본이 바뀌어도 살아남습니다.

> [!WARNING]
> 봉인된 섹션도 페이지에 남아 있습니다
>
> 리더 프레임이 감출 뿐, 마크다운에는 여전히 들어 있습니다. 콘텐츠 삭제는 편집이 아니라 제품 결정입니다.

## 아카이브의 문법

원본은 GFM에 네 가지 관례를 더합니다. 모두 공유 파이프라인이 처리하므로 모든 렌더러가 같은 결과를 냅니다.

| 관례 | 결과 |
| --- | --- |
| `\|\|text\|\|` | 독자가 열기 전까지 종이 뒤에 감춰지는 비공개 처리. |
| `![right\|caption](path)` | 정렬(왼쪽, 오른쪽, 전체)과 캡션이 있는 도판. |
| `> quote` | 인용문. 서류에서는 서신과 공지에 씁니다. |
| `\| table \|` | GFM 표. 파싱 전에 행을 복구하므로 셀 안의 비공개 처리도 작동합니다. |

원시 HTML은 통과되지 않습니다. 기록 안의 script 요소는 텍스트일 뿐이며, 원시 HTML을 허용하면 아카이브 자체의 문법 범례가 살아 있는 마크업이 됩니다.

다른 기록으로의 인용은 /site/records/CODE로 씁니다. 마크다운 문서는 어느 판본이 읽는지 알 수 없으므로, 열람판이 독자의 언어를 앞에 붙입니다.

## 기록이 있는 곳

본문은 components/reader/record-sources.ts에, 색인 항목은 components/browser/archive-index.ts에 있습니다. 본문 없이도 기록에 도달할 수 있습니다. 리더는 감춰진 형태를 보여 주며, 그것도 인터페이스의 실제 상태입니다.

CIRCA-S-03007은 렌더러의 테스트 코퍼스이며 의도적으로 색인에 들어 있습니다. 헤더, 비공개 처리가 있는 표, 세 가지 도판 정렬, 인용문, 코드 펜스를 모두 연습합니다.

> [!NOTE]
> 아직 CMS가 없습니다
>
> 오늘 기록을 추가하려면 그 두 TypeScript 모듈을 고쳐야 합니다. 백엔드가 생기면 렌더러는 계속 마크다운을 받고, 어디서 왔는지는 모른 채로 있어야 합니다.
