# 테스트

스위트는 인터페이스가 주장하는 것을 붙듭니다. 동작, 카탈로그, 원본 파싱, 두 판본.

## red, green, refactor

실패하는 동작 테스트를 먼저 쓰고, 통과하는 가장 작은 구현을 쓰고, 스위트가 초록인 상태에서 리팩터하세요. 이는 선호가 아니라 저장소의 규칙입니다. 나중에 붙인 테스트는 무엇이 옳은지보다 코드가 무엇을 하는지를 검증하기 쉽습니다.

해당 기능이 생기면 인가, 수명 주기 전이, 투표 고유성, 가시성을 우선하세요. 지금은 렌더러, 아카이브 규칙, 카탈로그 계약을 우선합니다.

## 단위 및 상호작용 테스트

Vitest는 jsdom에서 실행됩니다. 테스트는 client/tests/에 있고, 붙드는 표면이나 모듈의 이름을 따릅니다.

| 파일 | 내용 |
| --- | --- |
| `markdown-pipeline.test.ts` | 파싱, 비공개 처리, 도판, 경고, 코퍼스 계약. |
| `archive-site.test.tsx` | 열람판, 기록 페이지, 다운로드, 프로젝트 페이지. |
| `i18n-messages.test.ts` | 카탈로그 키 일치, 플레이스홀더, 리치 태그, 빈 값. |
| `desktop.test.tsx` | 워크스테이션 셸, 창, 상호작용. |
| `window-manager.test.tsx` | 지오메트리, 스태킹, 최소화, 최대화, 드래그 상태. |

카피를 읽는 컴포넌트에는 공급자가 필요합니다. 실제 카탈로그를 불러오는 tests/intl.tsx의 renderWithIntl을 쓰세요. 메시지 키가 아니라 독자가 보는 문장을 검증하게 됩니다.

## 카탈로그 계약

카탈로그 테스트는 영어와 한국어 카탈로그를 키 단위로 비교합니다. 플레이스홀더, 리치 텍스트 태그, 빈 값, 균형 잡힌 마크업, 그리고 일부 산문이 실제로 번역되었는지도 확인합니다.

영어 키를 먼저 추가하고 한국어를 넣으세요. 없는 키를 읽는 컴포넌트는 키 경로를 렌더링하므로, 이 테스트가 반쯤 끝난 번역을 잡습니다.

## 브라우저 테스트

Playwright는 3001 포트의 실제 서버에 대해 실행되며 playwright.config.ts에서 Chromium으로 설정됩니다. 반응형 동작과 언어 라우팅을 다룹니다.

```sh
bunx playwright install chromium
bun run test:e2e
```

설정은 서버가 이미 실행 중이 아니면 bun run dev를 시작합니다. 샌드박스에서는 PLAYWRIGHT_BROWSERS_PATH를 쓰기 가능한 디렉터리로 지정하세요.

## 무엇을 먼저 덮을까

커버리지 기준은 없습니다. 쓸모 있는 테스트는 막는 실패를 말합니다. 컴포넌트를 렌더링해 존재만 확인하는 테스트는 크래시를 막지 회귀를 막지 않습니다. 잘못된 문서가 거부되는지 검증하는 테스트는 유출을 막습니다.

알려진 간극은 표면별 README에 기록됩니다. 아카이브 내부 검색은 여전히 영어 클래스/상태 단어와 일치하고, 리더의 상대 시간은 영어로 남습니다. 테스트에서 간극을 조용히 좁히지 마세요.
