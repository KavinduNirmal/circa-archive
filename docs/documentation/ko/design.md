# 디자인 시스템

저장소는 세 가지 어조로 말합니다. 어느 어조에 있는지가 거의 모든 시각적 선택을 결정합니다.

## 세 시스템, 하나의 저장소

CIRCA 아카이브는 하나의 디자인 시스템이 아닙니다. 서로 다른 질문에 답하는 셋입니다.

| 시스템          | 표면       | 규칙                                                                                                  |
| --------------- | ---------- | ----------------------------------------------------------------------------------------------------- |
| 워크스테이션    | `/desktop` | 1990년대 제도권 소프트웨어: 강철, 베벨, 빽빽한 크롬, 12px. 데스크톱 바깥에서는 절대 쓰지 않습니다.    |
| 열람판          | `/site`    | 종이, 잉크, 세리프 마스트헤드, 접수된 문서. 깊이는 베벨이며 그라디언트는 없습니다.                    |
| 프로젝트 페이지 | `/meta`    | 따뜻한 기록용지, 번트 오렌지 잉크, Instrument Serif 디스플레이, 인쇄된 점 필드, 조용한 비대칭 에세이. |

> [!NOTE]
> 프로젝트 페이지는 예외입니다
>
> 아카이브와 다르게 보여도 되는 이유는 다른 질문에 답하기 때문입니다. 아카이브는 이름이 붙은 행동을 통해서만 이곳으로 연결되며, 프로젝트 페이지의 스타일은 아카이브로 넘어가지 않습니다.

## 프로젝트 페이지

프로젝트 사이트는 정적인 Astro 출판물입니다. 시각적 세계는 **인쇄된 필드가 있는 조용한 에세이**입니다. 거의 흰색인 따뜻한 종이 바탕, 하나의 번트 오렌지 액센트, 오른쪽으로 물러난 읽기 칼럼, 여백의 모노 출처 노트, 본문 앞에서 흐려지는 고정 하프톤 점 필드로 이루어집니다. 기록된 연구 중 Design E를 따릅니다.

스타일은 `meta/src/styles/` 아래에서 책임별로 나뉩니다. `tokens.css`, `base.css`, `layout.css`, `editorial.css`, `prose.css`, `documentation.css`, `print.css`가 `site.css`에서 이 순서로 불러옵니다. 규칙은 그 요소를 소유한 모듈에 넣으세요. 토큰을 사용하고, 두 번째 액센트나 그라디언트, 베벨, 그림자를 새로 만들지 마세요.

| 토큰             | 용도                                                            |
| ---------------- | --------------------------------------------------------------- |
| `--paper`        | 모든 페이지의 거의 흰색인 따뜻한 바탕.                          |
| `--paper-raised` | 내비게이션 바, 드롭다운 패널, 코드 표면.                        |
| `--ink`          | 제목과 주요 읽기 텍스트.                                        |
| `--ink-body`     | 긴 본문.                                                        |
| `--muted`        | 주석, 보조 문장, 레이블.                                        |
| `--accent`       | 링크, 두 번째 디스플레이 줄, 인장, 인쇄 필드. 단 하나의 액센트. |
| `--rule`         | 유일한 구조적 테두리인 헤어라인.                                |
| `--serif`        | 디스플레이, 섹션 제목, 리드, 인용의 Instrument Serif.           |
| `--sans`         | 읽기 문장과 컨트롤의 IBM Plex Sans.                             |
| `--mono`         | 코드, 주석, 내비게이션, 컨트롤의 IBM Plex Mono.                 |
| `--measure`      | 에세이는 620px, 마크다운 본문은 68ch까지.                       |

Noto Serif KR이 한국어 디스플레이와 제목을 맡고, 산스 스택이 한국어 읽기 문장을 보완합니다.

## 레이아웃과 내비게이션

셸은 1280px에서 중앙 정렬되고 여백은 유동적입니다. 넓은 화면에서 에세이는 왼쪽에서 22% 들어간 620px이며, 190px의 노트가 여백에 놓입니다. 노트는 1180px 아래에서 본문 흐름으로 들어옵니다. 여는 침묵, 섹션 간격, 행의 길이가 리듬을 만들며, 단계의 연속이 아니므로 섹션 번호는 쓰지 않습니다.

상단 바는 평평한 60px 모노 스트립입니다. 왼쪽에 워드마크, 오른쪽에 링크와 네이티브 디스클로저, 맨 끝에 언어 전환이 있습니다. 현재 페이지는 종이색 채움과 안쪽 잉크 밑줄을 받습니다. 내비게이션은 네이티브 `details`를 통해 자바스크립트 없이도 작동해야 합니다.

검색은 문서 리더에만 속합니다. 프로젝트 사이트에서 유일한 검색 필드이며, 문서 밖에서는 키보드 단축키가 아무 일도 하지 않습니다.

## 지킬 만한 패턴

- 하나의 액센트. 모든 것이 오렌지라면 아무것도 오렌지가 아닙니다.
- 카드 대신 헤어라인과 여백. 기록 발췌는 표면이 아니라 선으로 구획된 블록입니다.
- 점 필드는 장식입니다. 포인터를 받지 않고 콘텐츠 뒤에 있으며, 읽기 칼럼 앞에서 마스크로 사라지고 인쇄에서 숨습니다.
- 인장은 여백이나 푸터에 작고 평평하게 인쇄하고, 히어로 도판으로 쓰지 않습니다.
- 행동은 각진 모노 버튼과 분명한 레이블로 만듭니다. 알약, 배지, 아이콘만 있는 컨트롤은 쓰지 않습니다.
- 코드 표, 경고, 기록 메타데이터는 문서의 조용한 3단 리더 안에 머뭅니다.

## 접근성

WCAG 2.2 AA를 목표로 합니다. 본문은 종이 바탕에서 4.5:1을 넘고, 번트 오렌지 액센트는 작은 텍스트에서도 4.5:1을 넘으며 의미를 혼자 전달하지 않습니다. 링크에는 밑줄이 있고, 현재 페이지는 채움과 밑줄을 함께 쓰며, 포커스는 보이는 2px 링으로 표시합니다.

- 내비게이션, 챕터 그룹, 질문은 네이티브 `details`를 씁니다. Escape는 열린 메뉴를 닫고 포커스를 돌려놓습니다.
- 터치 대상은 내비게이션, 검색, 주요 행동에서 최소 44px입니다.
- 모션은 오프닝의 짧은 등장 하나이며, `prefers-reduced-motion`에서 사라집니다.
- 콘텐츠는 320px와 200% 확대에서 가로 넘침 없이 재배치됩니다. 표와 코드는 각자의 프레임 안에서 스크롤합니다.

## 페이지 추가하기

프로젝트 페이지는 `astro.config.mjs`에 등록하고 `Shell.astro`로 감싸는 `meta/src/routes/` 아래의 Astro 라우트입니다. 카피는 `meta/messages/`의 두 로케일 카탈로그에, 구성은 편집 클래스를 쓰는 컴포넌트나 라우트에 넣습니다. 문서 페이지는 `meta/src/lib/registry.ts`에 주제를 추가하고 `docs/documentation/{en,ko}/<slug>.md`에 원고를 둡니다.

아카이브의 크롬이나 워크스테이션의 베벨을 끌어오지 마세요. 완성해 보이게 하려고 글꼴, 그라디언트, 그림자를 더하지 마세요. 절제와 하나의 강한 제스처가 이 시스템입니다.
