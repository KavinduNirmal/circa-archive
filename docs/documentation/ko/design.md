# 디자인 시스템

저장소는 세 가지 어조로 말합니다. 어느 어조에 있는지가 거의 모든 시각적 선택을 결정합니다.

## 세 시스템, 하나의 저장소

CIRCA 아카이브는 하나의 디자인 시스템이 아닙니다. 서로 다른 질문에 답하는 셋입니다.

| 시스템          | 표면       | 규칙                                                                                                    |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------------- |
| 워크스테이션    | `/desktop` | 1990년대 제도권 소프트웨어: 강철, 베벨, 빽빽한 크롬, 12px. 데스크톱 바깥에서는 절대 쓰지 않습니다.      |
| 열람판          | `/site`    | 종이, 잉크, 세리프 마스트헤드, 접수된 문서. 깊이는 베벨이며 그라디언트는 없습니다.                      |
| 프로젝트 페이지 | `/meta`    | 근검정, 본, 엠버, 세리프 디스플레이, 모노 레이블, 헤어라인 필드. 워크스테이션 규칙에 얽매이지 않습니다. |

> [!NOTE]
> 프로젝트 페이지는 예외입니다
>
> 아카이브와 다르게 보여도 되는 이유는 다른 질문에 답하기 때문입니다. 아카이브는 이름이 붙은 버튼을 통해서만 이곳으로 연결됩니다.

## 프로젝트 페이지 토큰

프로젝트 페이지 토큰은 components/meta/meta.css의 .meta-page에 한 번 선언됩니다. 그것을 쓰고, 네 번째 액센트를 만들지 마세요.

| 토큰           | 용도                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| `--meta-ink`   | 모든 페이지 뒤의 근검정 캔버스.                                         |
| `--meta-bone`  | 기본 텍스트, 단색 버튼, 표본 문서.                                      |
| `--meta-mist`  | 보조 텍스트와 레이블. 작은 크기는 캡션용입니다.                         |
| `--meta-ember` | 색인 숫자, 링크, 포커스 링, 유일한 액센트. 유일한 신호로 쓰지 않습니다. |
| `--meta-line`  | 14% 본의 규칙과 테두리. 소프트 변형은 섹션을 나눕니다.                  |
| `--meta-serif` | 논증: 디스플레이 헤드라인, 섹션 제목, 인용, 이름.                       |
| `--meta-sans`  | 읽기 카피와 컨트롤. 본문 16–17px.                                       |
| `--meta-mono`  | 모든 레이블, 색인, 캡션, 명령, 코드 샘플.                               |

메타 범위는 shadcn 변수도 담습니다. components/ui의 프리미티브가 전역을 다시 칠하지 않고 이 팔레트를 물려받습니다. 메타 스타일은 범위를 지키세요. 워크스테이션 스타일시트가 들어오면 안 되고, 이 스타일시트가 나가면 안 됩니다.

## 지킬 만한 패턴

필드가 시각적 서명입니다. 측정된 그리드, 가장자리 해칭, 모서리 십자, 모노 상태 레일, CSS 점 스크린으로 만든 하프톤 도판. 장식이며 항상 aria-hidden입니다.

- 화면당 하나의 초점, 그다음 두 번째, 그다음 나머지.
- 카드 대신 헤어라인. 카드는 표면이지 기본 래퍼가 아닙니다.
- 숫자와 레이블은 모노, 논증은 세리프, 읽기 카피는 산스.
- 하나의 액센트. 모든 것이 엠버라면 아무것도 엠버가 아닙니다.

랜딩 페이지의 기준은 브로슈어가 아니라 계측 패널입니다. 상태선, 도판, 측정된 여백. 사람이 읽을 수 있는 세부를 더하고 소음을 더하지 마세요.

## 접근성

WCAG 2.2 AA를 목표로 합니다. 프로젝트 페이지 텍스트는 근검정 위의 본이나 미스트를 씁니다. 엠버는 레이블, 숫자, 포커스에 쓰이고 의미를 혼자 전달하지 않습니다.

- 모든 상호작용 요소에는 보이는 포커스 링이 있습니다: 2px 엠버, 오프셋.
- 모션은 짧은 등장 하나입니다. prefers-reduced-motion을 존중합니다.
- 모든 도판, 차트, 스크린샷은 텍스트 캡션이 있거나 aria-hidden인 장식입니다.
- 내비게이션과 언어 전환은 키보드로 닿을 수 있고, 모바일 드로어는 Radix Dialog로 포커스를 가둡니다.
- 콘텐츠는 320px와 200% 확대에서 기능 손실 없이 재배치됩니다.

컨트롤을 바꿀 때 대비와 포커스를 확인하세요. 정리 작업이 아니라 디자인의 일부입니다.

## 페이지 추가하기

프로젝트 페이지는 메타 라우트 아래의 서버 컴포넌트이고 공유 크롬으로 감쌉니다. 카피는 해당 로케일의 메타 카탈로그에, 스타일은 .meta-page 아래 meta.css에 넣습니다. 문서 페이지는 docs-topics.ts에 주제를, docs/documentation/{en,ko}/*.md에 섹션을 추가합니다.

아카이브의 크롬이나 워크스테이션의 베벨을 끌어오는 페이지를 추가하지 마세요. 완성해 보이게 하려고 두 번째 글꼴, 그라디언트, 그림자를 더하지 마세요. 시스템의 일은 하나의 강한 제스처와 절제입니다.
